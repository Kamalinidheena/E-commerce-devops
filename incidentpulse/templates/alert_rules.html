⚙️ Independent Alert Condition Engine

IncidentPulse evaluates two strictly decoupled rules for every check. A high-latency warning will never overwrite or falsely resolve a concurrent connection failure outage.

🚨

RULE 1 — Endpoint Failure (Critical)

Monitors socket reachability, DNS resolution, connection refusal, timeouts, and unacceptable HTTP status codes. Opens a CRITICAL incident when consecutive failures reach your configured limit.

  • Requires consecutive failures to filter out transient network blips.
  • Prevents duplicate incident creation during continuous outages.
  • Automatically detects recovery when consecutive successful checks occur.
⚠️

RULE 2 — Latency Threshold (Degraded)

Measures the actual HTTP response time in milliseconds. When response times exceed the millisecond threshold for consecutive samples, a WARNING / DEGRADED incident is recorded.

  • Detects performance bottlenecks even when the endpoint returns 200 OK.
  • Operates on independent streak counters.
  • Resolves automatically when latency returns below threshold for consecutive checks.
